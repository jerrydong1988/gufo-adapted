**Cache migration and rollback**

The inspected cache series keeps the disk envelope at `GUFOKVC1` / file version 1, while changing which prefixes, image identities and payload metadata are persisted/reused. `c362049` deliberately avoids reusing a legacy full checkpoint without an earlier fallback. This is not proof of safe bidirectional cache compatibility.

Validate with a separate cache directory and preserve the old directory for rollback. Include legacy full-only entries, new fallback/full entries, appended/reordered images and restart tests. Promotion should either retain cache separation or explicitly qualify old/new payload handling. Reverting source alone must not be treated as restoring old cache state. No launcher-config migration is required by the small recommended fixes.

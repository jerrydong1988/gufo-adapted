# Tool-calling failure diagnosis

Date: 2026-10-01. Follow-up to the
[PR #373 parser qualification](tool-calling-pr373.md#real-model-matrix).
The user authorized investigating the remaining generation and exact-edit
failures after that parser phase.

## Findings and retained change

There are three distinct problems:

1. The Qwen renderer trimmed leading/trailing whitespace from tool results.
   A read returned `"  before\n\n"`, but the rendered payload was `"before"`.
   Verification reads also hid the extra indentation and trailing blank lines.
   The checked-in reference Jinja template has the same trimming behavior.
2. Flash selects EOS inside a JSON string for certain literal tool markers.
   This happens before parsing and also reproduces in an independent runtime
   with the same GGUF weights and identical prompt token IDs.
3. Even after preserving the input, agents can select an incomplete `old_text`,
   alter replacement text or finish without checking exact contents. Restoring
   data fidelity alone does not establish agent task success.

The retained server change preserves Qwen tool-result text verbatim, including
whitespace-only content and whitespace beside image placeholders. Other roles
retain reference trimming. This is an intentional fork behavior beyond the
original parser-only phase. Both Qwen continuation compatibility identities
advance from formatter v3 to v4. The reference Jinja and its hashes are unchanged.
Implementation: `1a7da138a1003793dd701fc96a486fb61f9a3e75`.
There are no model arithmetic, sampling, stop-token or generation-constraint
changes, and no automatic escaping or repair of client content.

## Whitespace experiments

The original fixture starts as `"  before\n\n"`. Its requested replacement is
`"  after\nExample: <tool_call> </parameter> </tool_call>\n"`. The plain control
instead requests `"  after\n"`. Success always requires actual file bytes to
equal the target; a syntactically valid tool call is insufficient.

Baseline AR experiments with both Flash IQ4_XS and Qwen27B UD-Q4_K_XL fail
the raw and JSON-wrapped read variants. Raw reads typically produce doubled
indentation and extra blank lines. JSON-wrapped reads improve indentation but
still leave an extra newline. Flash's additional tool-description-only control
also fails. These controls were Chat Completions runs.

After the renderer change, the original agent and plain control still fail
through both APIs with both models. Qwen's original call leaves two surplus
newlines; Flash's original call now ends without a structured edit, leaving the
file unchanged. The latter is an observed generation change from the altered
prompt, not a claim that every tool-call metric improves. Both old and new
original exact-file gates remain failures.

The reusable [diagnostic harness](../../tests/tools/tool_whitespace_diagnose.py)
then controls read representation, edit semantics and verification instructions:

| AR model, both APIs | Explicit semantics + JSON read, plain target | Same plus escaped protocol target | Explicit verification/correction, plain target | Same with escaped protocol target |
| --- | --- | --- | --- | --- |
| Flash IQ4_XS | 0/2 | 0/2 | 2/2 | 2/2 |
| Qwen27B UD-Q4_K_XL | 0/2 | 0/2 | 2/2 | 0/2 |

Successful verification variants finish in four actions; none needs a corrective
retry. Qwen's protocol-literal recovery cases exhaust six turns with repeated
edits and incorrect final bytes. No repair or loop suppression is applied.
The changed verification instruction, not merely permission for more turns,
therefore affects these examples. These are bounded prompt comparisons, not a
general agent-quality score. JSON-wrapped reads already protect whitespace from
outer trimming, so their success must not be credited to the renderer fix.

Default behavior of `tool_parser_agent_check.py` remains the original test.
The diagnostic harness keeps every case separate and records `file_matches`
independently from action-order success. Recovery cases permit correction within
six turns and require a final read before finishing in a later response, so the
model can consume the read result. The full diagnostic runs
still return 1 because unsuccessful controls remain included.

## Flash termination experiments

An ignored standalone diagnostic, linked to the existing release engine, uses
`Model::Tokenize`, `Session::Sync`, greedy `SamplerState::Sample` and
`Session::Evaluate`. It records every selected token, the top eight logits and
SHA-256 of each complete raw-logit row. No tracing was added to server telemetry.
The original generated bytes exactly match the saved raw HTTP failure.

At the first premature stop, after 37 emitted tokens:

| Candidate | ID | Raw logit |
| --- | --- | --- |
| `<|im_end|>` | 248046 | 23.003225 |
| `<tool_call>` | 248058 | 22.240225 |

This is a real EOS selection, not a JSON parser boundary or output-token cap.
The budget is 256 tokens, context 4096, temperature 0 and seed 31, with AR and a
fresh session for each case. Each variant changes only the user argument example
in the actual rendered original prompt.

| Replacement example | Exact generated arguments | Emitted tokens before EOS |
| --- | --- | --- |
| Original three literal markers | Fail, truncated | 37 |
| Plain `after` | Pass | 44 |
| Indentation/newlines without markers | Pass | 50 |
| Only `<tool_call>` | Pass | 51 |
| Only `</parameter>` | Pass | 52 |
| Only `</tool_call>` | Fail, truncated | 37 |
| Three markers, no replacement newlines | Fail, truncated | 36 |
| Original example with JSON `\u003c` / `\u003e` escapes | Pass | 60 |

Escaping changes the prompt tokens while preserving the JSON example's decoded
meaning. The successful response still contains the requested literal markers.
This is a demonstrated prompt control, not a server fallback or universal fix.

The independent llama.cpp reference reports `0.4.1-dev`, build 1, commit
`3deeb337f9c11594b138c308db627177d94404dc`, using Clang 23.0.0.
It loads the same IQ4_XS shards, AR, GPU layers 99,
context 4096, one slot and flash attention. Its tokenizer produces exactly the
same 375 original prompt tokens. Completion requests then supply those token IDs
directly, with temperature 0, seed 31, repetition penalty 1 and eight reported
top log probabilities.

The reference also truncates the original JSON, after emitting one additional
`<tool_call>` token. At Gufo's exact failing history, the reference ranks
`<tool_call>` ahead of EOS (log probabilities -0.415336 and -1.080455).
One token later it selects EOS. Both runtimes complete the escaped example.
This reproduces the failure class independently but **does not establish full
numerical parity**: the differing top-1 at the matched prefix remains recorded.
An unquantized teacher would be needed to separate source-model behavior from
quantization effects. The observations do not justify a speculative kernel fix.

The MTP HTTP control uses the same shared Q8_0 sidecar, draft width 7, length
policy and full draft vocabulary as the original matrix. Both uncached and
repeated original requests emit exactly the AR failure (37 tokens); both escaped
requests emit exactly the complete AR response (60 tokens). Cached-token counts
are 0/375 for original and 0/407 for escaped. MTP proposes/accepts 34/31 and 59/47
draft tokens respectively. The failure is therefore not specific to speculation
or cache reuse in these controls.
